# AI Agents

## Назначение и структура

Локальная multi-agent система в `/opt/agents` на CT101. Python venv:
`/opt/agents/venv`; пользовательские рабочие файлы: `/opt/agents/workspace`.

- `agents/` — Coordinator, Executor, Developer и общий runtime. Подробности и
  локальные правила находятся в `agents/AGENTS.md` и в папке каждого агента.
- `web_service/` — Flask API, постоянная SQLite-очередь, worker и статический
  мобильный интерфейс. Подробности находятся в `web_service/AGENTS.md`.
- `tests/` — модульные и браузерные проверки; правила в `tests/AGENTS.md`.
- `ops/` — systemd units и эксплуатационные утилиты; правила в `ops/AGENTS.md`.
- `data/agents.sqlite3` — постоянные сессии и очередь; `workspace/` — общий
  пользовательский workspace. Эти каталоги не являются исходным кодом.

Применяй инструкции иерархически: сначала этот файл, затем ближайший `AGENTS.md`
в каталоге изменяемого модуля. При структурных изменениях обновляй соответствующие
`AGENTS.md`. В них хранятся архитектура, стабильные сведения о системе и правила,
без истории выполненных задач и отчётов о разовых проверках.

Запуск Coordinator: `venv/bin/python -m agents.coordinator`.
Запуск web-service: `venv/bin/python -m web_service`.
Тесты: `venv/bin/python -m pytest -q`.

## Общая архитектура

Web-service сохраняет пользовательскую задачу в SQLite. Единственный фоновый
worker передаёт её Coordinator. Coordinator выбирает Executor для пользовательских
файлов либо Developer для доработки `/opt/agents`, выдаёт одному агенту одну
подзадачу и принимает только компактный фактический результат. Structured-tool
runtime выполняет файловые и командные инструменты. Все обращения к локальной
модели проходят через llama.cpp API на CT100.

Делегации и ответы агентов с отметками времени сохраняются в SQLite и доступны
в web-интерфейсе. Максимальное ожидание ответа модели и одной делегации — 300 секунд.

Закрытие браузера не останавливает задачу. После перезапуска выполнявшаяся задача
помечается прерванной без автоматического повтора; ожидающие остаются в очереди.
Workspace общий для всех пользовательских сессий.

## Инфраструктура

Развёртывание состоит из Proxmox-хоста, отдельного inference-контейнера и
контейнера приложения. Конкретные адреса, SSH targets и внутренняя топология
хранятся только в игнорируемых `.env` и `AGENTS.local.md`. Шаблоны находятся в
`.env.example` и `AGENTS.local.md.example`. Перед инфраструктурной операцией прочитай
локальные настройки; не копируй их значения в tracked-файлы, сообщения commit или
вывод диагностики.

Контейнер inference запускается раньше контейнера приложения; порядок и задержка
старта описываются в локальном файле. `pve-guests.service` включена.

### Inference backend

- Backend работает через llama.cpp OpenAI-compatible API; URL задаётся отдельными
  переменными `*_LLM_URL`, readiness path — `/health`.
- Модель, GPU layout, объём ресурсов, бинарный путь и параметры запуска относятся
  к локальному deployment и хранятся только в `AGENTS.local.md` и локальных
  environment-файлах.
- Безопасные шаблоны unit и environment находятся в `ops/*.example`.
- Не увеличивай расход ресурсов без необходимости и не запускай две модели
  одновременно. Загрузка модели может занимать несколько минут.

## Доступ и эксплуатационные права

Пользователь разрешает самостоятельно выполнять действия с Proxmox и всеми
контейнерами в рамках поставленных задач: подключаться по SSH, менять конфигурацию
и ресурсы, управлять сервисами, моделями и контейнерами. В проекте разрешены
изменения кода, установка пакетов, запуск команд и тестов. Обязательные ограничения
инструментальной среды сохраняются.

Сервис работает от root, поэтому shell-инструменты локальных агентов технически
не изолированы. Ограничивай действия поставленной задачей, проверяй точную цель
перед удалением или остановкой и не запускай вторую копию модели.

## Git и чувствительные данные

Вся история хранится в GitHub, рабочая ветка — `master`. Каждое законченное
изменение сразу коммить в `master` с коротким описанием результата. Перед commit
проверяй staged-файлы на адреса, credentials, tokens, private keys, production DB,
workspace и эксплуатационные отчёты.

Реальные настройки хранятся только в игнорируемых `.env`, `AGENTS.local.md` и
локальных файлах без `.example`. В Git добавляются лишь обезличенные `*.example`.
Если чувствительное значение попало в commit, удали его из всей Git-истории до push;
одного последующего commit с удалением недостаточно.
