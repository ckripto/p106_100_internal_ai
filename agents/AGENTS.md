# Agents package

## Роли и поток управления

`coordinator/` планирует работу и выбирает агента. `executor/` работает только с
пользовательскими файлами в `/opt/agents/workspace`. `developer/` обслуживает сам
проект `/opt/agents`. `shared/` содержит транспорт и единый runtime structured tools.

Coordinator вызывает только одного агента за раз. Между агентами передаются статус,
краткое описание, пути файлов и метаданные команд; исходники и полный stdout не
переносятся. Success Coordinator допустим только после success агента с фактическим
выполнением инструмента. После тайм-аута Coordinator обязан изменить или сузить
подзадачу. Число решений, делегаций, ошибок протокола и тайм-аутов ограничено.

Каждый вызов LLM передаётся в общий `on_message`: запрос без системного prompt,
разобранный ответ либо контролируемая ошибка, номер шага и длительность ожидания.
Промпты требуют короткий `reason`, чтобы журнал отражал цель следующего действия
без публикации скрытой цепочки рассуждений.

## Границы модулей

- У каждого агента собственные `settings.py`, `prompt.md`, `agent.py` и `AGENTS.md`.
- Настройки среды читаются только в `settings.py` владельца.
- Промпты не встраиваются в Python. Изменение prompt требует перезапуска сервиса,
  поскольку агенты загружают его при импорте.
- Общая механика инструментов меняется в `shared/runtime.py`; специфическое
  поведение задаётся конфигурацией и prompt конкретного агента.
- HTTP/SQLite не импортируются в пакет агентов. Web-service зависит от публичного
  `agents.coordinator.run_coordinator`.

Подробный протокол описан в `README.md`. При добавлении агента создай отдельный
пакет по существующему шаблону, зарегистрируй runner в Coordinator и опиши границы
его полномочий.
