# Executor

Executor выполняет одну подзадачу через SSH на отдельном рабочем узле. Файловые
инструменты ограничены удалённым `EXECUTOR_REMOTE_WORKSPACE`; `run_command` также
выполняется удалённо и может устанавливать пакеты и обновления. На узле web-service
Executor не выполняет пользовательские команды и не хранит артефакты.

`settings.py` задаёт SSH target, удалённый workspace, inference URL, сроки
ответа/попытки/команды и step/chunk limits. `runtime.py` реализует SSH-выполнение и
атомарные удалённые файлы. `prompt.md` определяет рабочую дисциплину. `agent.py`
собирает настроенный `ToolAgent` и предоставляет `run_agent`.

Текущие defaults: 300 секунд на ответ модели, 300 секунд на попытку, 180 секунд на
команду, 60 шагов, chunk 600 символов. Переменные имеют префикс `EXECUTOR_`.
При тайм-ауте опубликованные файлы и завершённые команды сохраняются, staged части
отбрасываются; Coordinator получает `timed_out=true` и компактные факты.

Каждый запрос к LLM и разобранный tool call записываются через `on_message` с
номером шага и временем ответа. System prompt исключён; поле `reason` tool call
содержит краткую цель действия для оперативного журнала.

Пути tool calls всегда относительны к корню удалённого workspace; префикс
`workspace/` отклоняется, чтобы не создавать вложенный каталог по ошибке. Команды
выполняются удалённо через Bash с `pipefail`, поэтому ошибка элемента pipeline не
маскируется последней успешной командой. SSH работает в BatchMode; недоступный узел
даёт контролируемый failed без локального fallback.
