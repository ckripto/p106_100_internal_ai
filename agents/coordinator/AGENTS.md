# Coordinator

`agent.py` содержит конечный цикл планирования. Он хранит компактную историю
делегаций только в памяти текущей задачи, валидирует управляющий JSON, вызывает
зарегистрированный runner синхронно и возвращает web-service итоговый final.

Маршрутизация: задачи о пользовательских файлах идут `executor`; изменения
агентской системы, web-service, тестов, документации и ops идут `developer`.
Сложная работа делится на последовательные проверяемые этапы. После `timed_out`
нельзя повторить ту же пару agent/task; сначала проверяется сохранившееся состояние.

`settings.py` владеет URL и тайм-аутом Coordinator, лимитами делегаций, тайм-аутов,
ошибок протокола, длины задачи и истории. `prompt.md` владеет политикой решений и
JSON-форматом. Python должен обеспечивать инварианты независимо от послушности
модели: допустимые agent/status, конечные лимиты и подтверждение success.

Публичный интерфейс:
`run_coordinator(task, history=None, on_progress=None, on_message=None)`.
`on_message` получает запрос и разобранное решение каждого обращения Coordinator
к LLM, request до запуска runner и response после его завершения. LLM request не
содержит system prompt; response содержит решение или тип контролируемой ошибки и
фактическое время ожидания по монотонным часам. В межагентные сообщения попадает
тот же компактный результат, который получает следующий шаг Coordinator.
Добавление нового типа управляющего сообщения требует теста каждой ветви и
обновления prompt/README.
